# ewsnotifier

[![CI](https://github.com/poznik/ewsnotifier/actions/workflows/ci.yml/badge.svg)](https://github.com/poznik/ewsnotifier/actions/workflows/ci.yml)

Уведомления из Microsoft Exchange (EWS) в Telegram: встречи на сегодня и
непрочитанная почта, два бота.

English version: [README.md](README.md).

## Что умеет

- Опрашивает Exchange по EWS (on-premises серверы с NTLM/Basic/Digest,
  autodiscover не нужен), кэширует календарь на сегодня и свежую
  непрочитанную почту.
- **Бот встреч**: напоминание незадолго до начала каждой встречи с кнопкой
  «Подключиться», если в месте встречи есть ссылка; команды `/today`
  (расписание дня с «окнами» между встречами) и `/check` (пересечения
  встреч); опциональная утренняя сводка по будням.
- **Бот почты**: сообщение о каждом новом непрочитанном письме — отправитель,
  тема, короткое превью; упоминание (например, `@nickname`) при ключевых
  словах в тексте.
- Служебные алерты: если сломалась авторизация в Exchange (протух пароль),
  бот сообщает об этом в админский чат и повторяет попытки с большим
  интервалом, а не молча показывает устаревшие данные.
- Состояние уведомлений переживает рестарты — после обновления версии не
  будет шквала повторных сообщений.

## Быстрый старт (локально)

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # заполнить значения
python -m notifier
```

## Быстрый старт (Docker / Synology)

1. Скопируйте проект на хост, например в `/volume1/docker/notifier`.
2. Создайте `.env` рядом с `docker-compose.yml` (за основу — `.env.example`).
3. Создайте каталог состояния; он должен быть доступен на запись
   пользователю из `user:` в `docker-compose.yml` (по умолчанию `1026:100` —
   поправьте на вывод `id <ваш-пользователь>` на хосте):

   ```bash
   mkdir -p data
   ```

4. Запустите:

   ```bash
   docker compose up -d --build
   ```

На Synology DSM можно импортировать `docker-compose.yml` через
Container Manager → «Проекты». Переменные среды, заданные в UI, имеют
приоритет над значениями из `.env`.

В контейнере настроен `HEALTHCHECK`: статус становится unhealthy, если
данные из Exchange не обновлялись дольше `HEALTH_MAX_AGE` секунд
(по умолчанию 600).

## Настройки

Параметры читаются из переменных среды; недостающие берутся из файла
`.env` в рабочем каталоге. При старте все ошибки конфигурации выводятся
сразу списком с именами переменных.

### Обязательные

| Переменная | Значение |
| --- | --- |
| `EWS_SERVER` | Адрес Exchange, например `mail.example.com` |
| `EWS_EMAIL` | Основной SMTP-адрес ящика |
| `EWS_USERNAME` | Логин, обычно `DOMAIN\user` (см. про бэкслэш ниже) |
| `EWS_PASSWORD` | Пароль |
| `UPDATE_INTERVAL` | Период обновления данных из Exchange, сек |
| `APPOINTMENT_REFRESH_INTERVAL` | Период проверки напоминаний о встречах, сек |
| `APPOINTMENT_NOTIFY_INTERVAL` | За сколько секунд до встречи напоминать |
| `MAIL_REFRESH_INTERVAL` | Период отправки накопленных писем, сек |
| `APPOINTMENT_BOT_TOKEN` | Токен Telegram-бота встреч |
| `MAIL_BOT_TOKEN` | Токен Telegram-бота почты |
| `ALLOWED_CHAT_IDS` | ID чатов через запятую: им доступны команды и уведомления |
| `LOCAL_TIMEZONE` | Часовой пояс IANA, например `Europe/Moscow` |

### Необязательные

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `EWS_AUTH_TYPE` | `NTLM` | `NTLM`, `BASIC` или `DIGEST` |
| `EWS_VERIFY_SSL` | `true` | Проверка TLS-сертификата (см. «Безопасность») |
| `ADMIN_CHAT_ID` | — | Чат для служебных алертов; пусто = алерты в `ALLOWED_CHAT_IDS` |
| `MAIL_LOOKBACK_DAYS` | `7` | Учитывать непрочитанные не старше стольких дней |
| `MAIL_FETCH_LIMIT` | `100` | Максимум писем за одно обновление |
| `KEYWORDS` | — | Ключевые слова через запятую (по границам слов) для упоминания |
| `MENTION_TEXT` | — | Текст упоминания при срабатывании, например `@nickname` |
| `AGENDA_TIME` | — | `HH:MM` локального времени; утренняя сводка по будням |
| `WORKDAY_START` | `09:00` | Начало рабочего дня для «окна» до первой встречи |
| `MASK_PRIVATE_MEETINGS` | `false` | Скрывать темы приватных встреч |
| `AUTH_RETRY_INTERVAL` | `1800` | Пауза между попытками после ошибки авторизации, сек |
| `STATE_FILE` | `state.json` | Файл состояния уведомлений (`/data/state.json` в Docker) |
| `HEALTH_FILE` | `/tmp/notifier-healthy` | Маркер свежести для healthcheck |
| `LOG_LEVEL` | `INFO` | `CRITICAL` … `DEBUG` |

### Как записать `DOMAIN\user`

Правила экранирования различаются — это самая частая ошибка настройки:

| Где | Как писать | Почему |
| --- | --- | --- |
| Файл `.env` | `EWS_USERNAME=DOMAIN\user` | Значения читаются буквально, без экранирования |
| YAML (`docker-compose.yml`) | `EWS_USERNAME: "DOMAIN\\user"` | YAML превращает `\\` в `\` |
| Shell | `export EWS_USERNAME='DOMAIN\user'` | Одинарные кавычки сохраняют строку как есть |

## Детали поведения

- Напоминание о встрече отправляется один раз; при переносе встречи
  (в любую сторону) — отправляется заново.
- События «весь день» показываются в `/today` отдельной строкой
  «Весь день» и не участвуют в напоминаниях и `/check`.
- Отменённые встречи игнорируются.
- При самом первом запуске накопленные непрочитанные письма не
  вываливаются в чат — уведомления идут только о новых.
- Длинные ответы `/today` и `/check` режутся под лимит Telegram.
- Сообщения, которые Telegram отверг навсегда, логируются и пропускаются;
  сетевые сбои и flood-контроль повторяются.

## Безопасность

- Держите `EWS_VERIFY_SSL=true`. Отключение проверки позволяет перехватить
  NTLM-учётку любому на пути трафика; при выключенной проверке приложение
  пишет предупреждение в лог. Для самоподписанного корпоративного CA
  укажите `REQUESTS_CA_BUNDLE` на ваш сертификат.
- Секреты живут только в `.env` / переменных среды; файл исключён из git
  и не попадает в Docker-образ.
- Контейнер работает не от root; команды обслуживаются только для чатов
  из `ALLOWED_CHAT_IDS`.
